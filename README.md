# Go Battle Live — คู่มือติดตั้งและใช้งาน

เกมหมากล้อมออนไลน์ 2 คน กติกาตามสมาคมกีฬาหมากล้อมแห่งประเทศไทย
พร้อมระบบสมาชิก ระบบดั้ง AI หลายระดับ และห้องคอนโทรลสำหรับสลับห้องขึ้นถ่ายทอดสด

---

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `go-engine.js` | เอนจินกติกาโกะแบบญี่ปุ่น ใช้ร่วมกันทั้งเซิร์ฟเวอร์และเบราว์เซอร์ |
| `ai-light.js` | AI ชั้นเบา ระดับ 20–8 คิว ไม่ต้องใช้เครื่อง AI แยก |
| `server.js` | เซิร์ฟเวอร์กลาง Node + WebSocket — เจ้าของ state และนาฬิกาทั้งหมด |
| `schema.sql` | โครงฐานข้อมูล Supabase (สมาชิก ดั้ง เกม RLS) |
| `public/index.html` | หน้าเว็บผู้เล่น |
| `public/director.html` | ห้องคอนโทรลเบื้องหลัง |
| `public/live.html` | ภาพออกอากาศแนวตั้ง 1080×1920 สำหรับ OBS / TikTok Live Studio |
| `test.js` | ทดสอบเอนจิน 16 ข้อ รวมการเล่นเอง 150 เกม |
| `test-server.js` | ทดสอบเซิร์ฟเวอร์ครบวงจร 72 ข้อ |

## ติดตั้งใน 5 ขั้นตอน

### 1. ตั้งฐานข้อมูล Supabase

1. สร้างโปรเจกต์ใหม่ที่ supabase.com (แผนฟรีพอ)
2. เปิดเมนู **SQL Editor** → **New query**
3. คัดลอกเนื้อหาทั้งไฟล์ `schema.sql` วางลงไป → กด **Run**
   (รันซ้ำได้ ไม่พัง)
4. ไปที่ **Authentication → Providers** เปิด **Email** ไว้
   ถ้าอยากให้สมัครแล้วเข้าใช้ได้ทันทีโดยไม่ต้องยืนยันอีเมล ให้ปิด *Confirm email*
5. ไปที่ **Project Settings → API** จดค่าไว้ 3 อย่าง
   - `Project URL`
   - `anon public` key — ใช้ในหน้าเว็บ **เปิดเผยได้**
   - `service_role` key — ใช้ในเซิร์ฟเวอร์ **ห้ามหลุดไปฝั่งเบราว์เซอร์เด็ดขาด**

### 2. ทดสอบในเครื่องก่อน

```bash
npm install
npm test        # ต้องผ่านทั้ง 16 + 53 ข้อ
npm start       # เปิด http://localhost:3000
```

ตอนนี้ยังไม่ต้องใส่ค่า Supabase ก็เล่นได้ เพียงแต่จะไม่บันทึกผลและไม่มีดั้ง
กด **เล่นเลยแบบผู้มาเยือน** เพื่อลองได้ทันที

เปิดสองแท็บเพื่อลองเล่นสองคน หรือกด **ซ้อมกับ AI** เพื่อเล่นคนเดียว

### 3. ใส่ค่า Supabase ในหน้าเว็บ

**ใส่ให้แล้วในไฟล์ `public/index.html`** — ทั้ง Project URL และ anon key
ถ้าเปลี่ยนโปรเจกต์ในอนาคต ให้แก้ตรงหัวข้อ `CONFIG` ประมาณกลางไฟล์
โดย **URL ต้องไม่มีเครื่องหมาย `/` ปิดท้าย** ไม่งั้น supabase-js จะต่อ path ผิด

### 4. ดีพลอยเซิร์ฟเวอร์บน Render

1. push โค้ดขึ้น GitHub
2. Render → **New → Web Service** → เลือก repo นี้
3. ตั้งค่า
   - Runtime: **Node**
   - Build Command: `npm install --omit=dev`
   - Start Command: `node server.js`
   - Health Check Path: `/healthz`
   - **Instance Type: Starter ($7/เดือน)**
4. ใส่ Environment Variables

   | ชื่อ | ค่า |
   |---|---|
   | `SUPABASE_URL` | Project URL จากขั้นตอนที่ 1 |
   | `SUPABASE_SERVICE_KEY` | service_role key |
   | `DIRECTOR_TOKEN` | รหัสลับที่ตั้งเอง สำหรับเข้าห้องคอนโทรล |
   | `AI_DELAY_MS` | `600` (หน่วงให้ AI ดูเหมือนกำลังคิด) |

> **อย่าใช้แผน Free** — เครื่องจะหลับหลังไม่มีคนใช้ 15 นาที ทำให้ WebSocket ของทุกห้องขาดพร้อมกัน
> และโควตา 750 ชั่วโมง/เดือนเปิดค้างได้แค่บริการเดียว
> ส่วนฐานข้อมูลให้ใช้ Supabase เท่านั้น เพราะ Postgres ฟรีของ Render จะถูกลบทิ้งหลัง 30 วัน

ไฟล์ `render.yaml` ในโปรเจกต์ตั้งค่าทั้งหมดนี้ไว้แล้ว ใช้ Blueprint ได้เลย

### 5. เปิดห้องคอนโทรลและตั้งภาพออกอากาศ

**ห้องคอนโทรล** — เข้า `https://ชื่อบริการของคุณ.onrender.com/director`
ใส่รหัสที่ตั้งไว้ใน `DIRECTOR_TOKEN`

**ถ้าไม่มีคอมพิวเตอร์ — ใช้ iPhone 2 เครื่อง** ดูหัวข้อถัดไป

**ภาพออกอากาศใน OBS** —
1. เพิ่ม Source → **Browser**
2. URL: `https://ชื่อบริการของคุณ.onrender.com/live`
3. Width **1080** · Height **1920**
4. ติ๊ก *Shutdown source when not visible* ออก เพื่อไม่ให้ภาพขาดตอนสลับฉาก
5. ถ้าจะใช้เสียง ให้เพิ่ม flag `--autoplay-policy=no-user-gesture-required` ตอนเปิด OBS

เลือกทรานซิชันด้วยแถบที่อยู่ได้: `/live?t=ink` (ปัดหมึก ค่าเริ่มต้น) · `?t=fade` · `?t=cut`
ลองดูคัตซีนโดยไม่ต้องมีเกมจริง: `/live?demo=1`

## ถ่ายทอดสดด้วย iPhone 2 เครื่อง (ไม่ต้องใช้ OBS)

ระบบรองรับกรณีนี้โดยเฉพาะ — **เครื่อง A เล่น เครื่อง B ถ่ายทอด** ไม่ต้องมีคนคุมห้องคอนโทรลเลย

### เตรียมเครื่อง B (เครื่องถ่ายทอด) ครั้งเดียว

1. เปิด Safari ไปที่ `https://ชื่อบริการของคุณ.onrender.com/live?auto=1`
2. กดปุ่ม **แชร์** → **เพิ่มไปยังหน้าจอโฮม** ตั้งชื่อว่า "Go Battle LIVE"
   > ขั้นนี้สำคัญมาก เพราะเปิดจากไอคอนหน้าโฮมจะเต็มจอ **ไม่มีแถบที่อยู่ของ Safari ติดไปในภาพ**
3. เปิดจากไอคอนที่เพิ่งสร้าง แล้วกด **แตะเพื่อเริ่ม**
   ปุ่มนี้ทำสองอย่าง: ปลดล็อกเสียง (iPhone บังคับให้มีการแตะก่อน) และสั่งไม่ให้หน้าจอดับระหว่างถ่ายทอด
4. เปิด **โหมดห้ามรบกวน (Focus)** กันการแจ้งเตือนเด้งขึ้นกลางไลฟ์

### ตอนจะถ่ายทอด

| เครื่อง | ทำอะไร |
|---|---|
| **A — เครื่องเล่น** | เปิดเว็บหลัก สร้างห้อง เล่นตามปกติ |
| **B — เครื่องถ่ายทอด** | เปิดไอคอน Go Battle LIVE → เปิด TikTok → `+` → เลื่อนไปโหมด **LIVE** → ตั้งชื่อ → ในเมนู **…** เลือก **แชร์หน้าจอ** → เลือกแอป Go Battle LIVE → เริ่มถ่ายทอด |

**`?auto=1` คือหัวใจของโหมดนี้** — เซิร์ฟเวอร์จะเลือกห้องขึ้นภาพให้เอง
โดยยกห้องที่กำลังเล่นและมีค่าความมันสูงสุดขึ้นมา ค้างห้องละอย่างน้อย 30 วินาที
ห้องที่เพิ่งจบจะค้างหน้าจอผลไว้อีก 8 วินาทีก่อนสลับ ถ้าไม่มีใครเล่นเลยจะขึ้นจอรอ

ที่สำคัญคือ **ตรรกะนี้อยู่ที่เซิร์ฟเวอร์ ไม่ใช่ที่หน้าเว็บ** เครื่อง B จึงแค่แสดงภาพอย่างเดียว
ไม่ต้องมีใครกดอะไรตลอดการถ่ายทอด และถ้าเครื่อง B หลุดเน็ตชั่วครู่ พอกลับมาก็ต่อภาพได้เอง

### จะแทรกข้อความ MC หรือยิงคัตซีนระหว่างไลฟ์

เปิด `/director` บนเครื่อง A ก็ได้ (สลับแอปไปมา) หรือให้เพื่อนเปิดจากเครื่องอื่น
แต่พอเปิดหน้าเบื้องหลัง **โหมดอัตโนมัติจะถูกปิดทันที** เพราะถือว่ามีคนคุมแล้ว
ถ้าอยากให้กลับไปอัตโนมัติ ให้ติ๊กช่อง **สลับอัตโนมัติ** ในหน้านั้น

### ข้อจำกัดที่ต้องรู้ล่วงหน้า

- **TikTok LIVE ต้องมีผู้ติดตาม 1,000 คนขึ้นไป และอายุ 18 ปีขึ้นไป** ถึงจะเปิดใช้ได้
  ถ้ายังไม่ถึงเกณฑ์ ทางเลือกที่ใช้ได้จริงคือให้คนที่เปิดไลฟ์ได้ชวนเราเป็น **แขกร่วมไลฟ์ (guest)**
  เพราะฝั่งแขกไม่ต้องผ่านเกณฑ์เอง
- การแชร์หน้าจอบนมือถือจะจับ**ทั้งหน้าจอ** รวมถึงการแจ้งเตือนที่เด้งขึ้นมา จึงต้องเปิดโหมดห้ามรบกวน
- หน้าจอ iPhone สูงกว่าสัดส่วน 9:16 หน้าออกอากาศจึงยืดความสูงให้เต็มจอเอง
  และเผื่อพื้นที่ด้านล่าง 30% ไว้ให้คอมเมนต์กับปุ่มของ TikTok ไม่ทับกระดาน
- ถ่ายทอดต่อเนื่องนาน ๆ เครื่องจะร้อนและแบตหมดเร็ว ควรเสียบชาร์จไว้ตลอด

## วิธีใช้งาน

### ผู้เล่น
1. สมัครสมาชิกด้วยอีเมล หรือกด **เล่นเลยแบบผู้มาเยือน**
2. เลือกขนาดกระดานและเวลา แล้วกด **สร้างห้องรอคู่แข่ง**
3. กดปุ่ม **รหัส** มุมขวาบนเพื่อคัดลอกลิงก์ห้อง ส่งให้เพื่อน
   เพื่อนเปิดลิงก์แล้วเข้าห้องได้เลยไม่ต้องพิมพ์รหัส
4. ทั้งสองฝ่ายกด **พร้อมแล้ว** เกมเริ่มทันที
5. **บนมือถือ** แตะกระดานเพื่อเล็งจุดก่อน แล้วกด **วางตรงนี้** เพื่อยืนยัน — กันวางพลาด
   **บนคอมพิวเตอร์** คลิกวางได้เลย
6. เมื่อไม่มีที่จะเล่นแล้ว กด **ผ่าน** ทั้งสองฝ่าย
7. เข้าเฟสนับแต้ม — แตะหมู่หมากที่ตายแล้วเพื่อกากบาท เงาพื้นที่จะอัปเดตให้ดูทันที
   ทั้งสองฝ่ายกด **ยืนยันนับแต้ม** ระบบจะประกาศผล
8. กด **บันทึก SGF** เพื่อเก็บเกมไว้ทบทวนหรือส่งให้ครูดู

### ภาพออกอากาศ (live.html)
หน้านี้อ่านอย่างเดียว ไม่มีปุ่มอะไรเลย รับภาพจากห้องที่ผู้กำกับเลือกไว้เท่านั้น ประกอบด้วย
- การ์ดผู้เล่นบน–ล่าง (ขาวบน ดำล่าง ตามธรรมเนียมการถ่ายทอดโกะ) พร้อมดั้ง นาฬิกา และจำนวนเชลย
- แถบประเมินคะแนนสด คำนวณจากแผนที่อิทธิพลอย่างง่าย บวกเชลยและโคมิ
- กระดานใหญ่ตรงกลาง มีจุดตราประทับสีชาดที่ตาล่าสุด และกรอบเตือนจุดติดโคะ
- กล่องข้อความ MC ด้านล่าง
- **คัตซีนค่ายกล 3 วินาที** — จอมืดลง เส้นสปีดไลน์แดง ป้ายชื่อค่ายกลไทย–ญี่ปุ่น รอยพู่กันหมึกกางออก
  และวงทองเรืองแสงรอบจุดค่ายกลบนกระดาน **ผู้เล่นไม่เห็นและเกมไม่หยุดเดิน**

### ผู้กำกับ (director.html)
- การ์ดทุกใบคือห้องที่กำลังเล่นอยู่ พร้อมกระดานย่อที่อัปเดตสด
- แถบสีล่างการ์ดคือ **ค่าความมัน** คำนวณจากการจับกินล่าสุด สถานะเบียวโยมิ และจำนวนตา
- แตะการ์ด → เข้าช่อง **PREVIEW** → กด **TAKE** เพื่อส่งขึ้นออกอากาศ
- ติ๊ก **สลับอัตโนมัติ** ให้ระบบเลือกห้องที่มันที่สุดเอง โดยค้างห้องละอย่างน้อย 30 วินาที
- ปุ่ม **จอดำ** ตัดภาพออกทั้งหมด ใช้ตอนพักหรือมีปัญหา
- ช่อง **ข้อความ MC** พิมพ์แล้วกดส่ง ขึ้นบนภาพออกอากาศทันที
- ช่อง **ยิงคัตซีนค่ายกล** เลือกชื่อค่ายกลแล้วกดยิง ระบบจะเน้นตาล่าสุดของห้องที่ออกอากาศให้
  (ตอนนี้ยิงด้วยมือก่อน ส่วนตัวตรวจจับอัตโนมัติเป็นงานเฟสถัดไป)

## สิ่งที่ระบบทำไว้ให้แล้ว

**กติกา** — นับแต้มแบบญี่ปุ่น, โคมิผูกกับขนาดกระดานตามที่สมาคมฯ ประกาศ
(9×9 = 1.5 · 13×13 = 3.5 · 19×19 = 6.5), โคะแบบง่าย, ตรวจซันโคะเป็นไม่มีผลแพ้ชนะ,
ดาเมะไม่นับเป็นแต้ม, หยุดนาฬิกาก่อนตกลงหมากตาย, ห้ามวางฆ่าตัวตาย, แต้มต่อทำให้โคมิเป็น 0

**นาฬิกา** — เวลาหลัก + เบียวโยมิหลายรอบ เดินทันในรอบแล้วรอบรีเซ็ตให้ถูกต้อง
เซิร์ฟเวอร์เป็นเจ้าของเวลาแต่เพียงผู้เดียว เบราว์เซอร์แค่วาดตาม

**ดั้ง** — เก็บเป็น GoR (1 ระดับ = 100 แต้ม = แต้มต่อ 1 เม็ด) แยกตามขนาดกระดาน
10 เกมแรกเป็นช่วงทดลอง เกมกับ AI คิดที่น้ำหนักครึ่งเดียว
คู่เดิมเจอกันเกิน 3 เกมใน 24 ชั่วโมงไม่คิดคะแนน

**ความปลอดภัย** — RLS ปิดไม่ให้เบราว์เซอร์เขียนคะแนนหรือแก้ยศตัวเอง
การบันทึกผลและปรับดั้งทำโดยเซิร์ฟเวอร์ด้วย service key เท่านั้น

**เสียง** — Web Audio ล้วน แยกบัส bgm/sfx/voice, BGM ใช้ `loop = true` จึงไม่มีทางเงียบเองตอนจบแทร็ก
เซิร์ฟเวอร์ส่งมาแค่ “ชื่อเสียง” ทุกเครื่องเล่นจากไฟล์ของตัวเอง จึงไม่มีอาการเสียงดังแค่ฝั่งโฮสต์
ตอนนี้ใช้เสียงสังเคราะห์ไปก่อน ยังไม่ต้องอัปโหลดไฟล์ใด ๆ

**ความทนทาน** — ไม่มี P2P ไม่มีการย้ายโฮสต์ หลุดแล้วกลับเข้าที่นั่งเดิมได้ภายใน 60 วินาที
เกินกว่านั้นปรับแพ้ ห้องร้างถูกเก็บกวาดอัตโนมัติ

## ขั้นตอนถัดไปที่ยังไม่ได้ทำ

1. **ตัวตรวจจับค่ายกลอัตโนมัติ** — ตอนนี้คัตซีนพร้อมใช้แล้วแต่ต้องยิงด้วยมือ
   ขั้นถัดไปคือให้เซิร์ฟเวอร์ตรวจหลังทุกตาเดิน (ค่ายกลย้อนศร อาตาริคู่ แทงกลางตา บันได เซกิ ฯลฯ)
   แล้วยิง `{t:'highlight'}` เอง — ช่องทางส่งข้อมูลทำเสร็จแล้ว เหลือแค่ตัวตรวจจับ
2. **ตัวละครในคัตซีน** — ตอนนี้เป็นป้ายชื่อค่ายกล ยังไม่มีภาพตัวละคร

3. เชื่อม TikTok Live ผ่าน `tiktok-live-connector` และให้คนดูโหวตเลือกห้อง
4. AI ระดับดั้งด้วย KataGo Human SL บนเครื่องแยก
5. `db.html` หน้าสถิติและตารางอันดับ
6. อัปโหลดไฟล์เพลงและเสียงจริงเข้า Supabase Storage แทนเสียงสังเคราะห์

## ถ้าดีพลอยแล้ว build ไม่ผ่าน

**`npm error ... Run "npm help ci" for more info` แล้ว Build failed**
เกิดจากคำสั่ง `npm ci` ที่ต้องมีไฟล์ `package-lock.json` อยู่ใน repo เสมอ ถ้าไม่มีจะพังทันที
แก้ได้ 2 ทาง เลือกทางใดทางหนึ่ง

1. **เปลี่ยนคำสั่ง build** (ทำไว้ให้แล้วใน `render.yaml`)
   Render → Settings → Build Command → `npm install --omit=dev`
   คำสั่งนี้สร้าง lockfile เองได้ จึงไม่ต้องมีไฟล์นั้นใน repo
2. หรือ **commit `package-lock.json` ขึ้น repo** แล้วใช้ `npm ci --omit=dev` ต่อไปได้
   (แนะนำในระยะยาว เพราะล็อกเวอร์ชันไลบรารีไว้ไม่ให้เปลี่ยนเอง)

> ถ้าแก้ใน `render.yaml` อย่างเดียวแล้วยังพัง ให้ไปแก้ที่ Render → Settings → Build Command ด้วย
> เพราะค่าที่ตั้งไว้ในหน้าเว็บ Render จะทับค่าจากไฟล์
